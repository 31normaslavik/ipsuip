# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 0.1.x  | Да        |
| < 0.1  | Нет       |

## Сообщение об уязвимости

Не создавайте публичный issue. Используйте приватный канал
[GitHub Security Advisories → Report a vulnerability](https://github.com/31normaslavik/ipsuip/security/advisories/new).

Пожалуйста, приложите:

- версию (`ipsuip --version`) и ОС;
- шаги воспроизведения и минимальный пример;
- потенциальное влияние (утечка данных, запись файлов и т.д.).

Мы подтверждаем получение в течение 7 дней и стремимся выпустить исправление
в течение 30 дней для поддерживаемых версий.

## Настройки репозитория (для мейнтейнера)

- Branch protection для `main`: обязательный PR, 1 одобрение, зелёные CI/CodeQL,
  запрет прямых push и force-push.
- Tag protection для `v*`; теги создаёт только мейнтейнер.
- Включить secret scanning и Dependency graph, приватный reporting (см. выше).
- Требовать подписанные коммиты/теги, если ключи доступны мейнтейнерам.

Сейчас репозиторий приватный: GitHub API отклоняет включение branch/tag
protection и secret scanning с сообщением «Upgrade to GitHub Pro or make this
repository public». После смены тарифа или публикации репозитория примените
настройки выше; до этого их соблюдение лежит на мейнтейнерах.

## Что считается уязвимостью

Ошибки проверки TLS-сертификатов, запись учётных данных прокси в
общедоступные файлы, произвольная запись файлов через `--output`, проблемы
с разбором range/CIDR, ведущие к инъекциям в сохраняемые файлы.
